# Codex Fleet Manager v0.5.0

## Fix: reserved Codex tool schemas during retries

Some CPA versions normalize tool parameter types before invoking plugin
executors. For Codex Desktop requests routed through CFM's retry executor,
this could change `collaboration.wait_agent.timeout_ms` from `number` to
`integer`. ChatGPT rejects the modified reserved-tool schema; the resulting
upstream HTTP 400 could surface as `host_call_failed` HTTP 500.

CFM now restores existing `collaboration` function parameter definitions from
CPA's untouched `OriginalRequest` before the initial and fallback attempts.
Unrelated tool definitions, host payload settings, model selection, and
reasoning handling remain intact. Additional-tools history is covered too.
Missing, malformed, or ambiguous original definitions leave the payload
unchanged. No settings migration or new configuration is required.

## Compatibility and verification

- Full Go test suite and `go vet` passed.
- Isolated request-forwarding tests passed with CPA v8.0.32 and v8.0.69.
- A live gpt-6.1-sol Responses request with the affected tool type completed
  successfully on CPA v8.0.69 using the same restoration code.
- Older CPA requests whose reserved schemas are unchanged remain byte-identical
  through the restoration step.

These checks target this regression rather than every CPA feature or provider.
The host must expose the original request to the plugin for restoration to work.
